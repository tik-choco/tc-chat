App policy lives in config.ts, checkpoint.ts and controller.ts. The adapter uses the existing singleton mist wrapper. SPEC2 W3 uses a room-id-deduplicated registry for the active shared room and accepted DMs, capped at eight concurrent controllers. The active room is pinned; accepted DM wire activity rotates the least recently used background entry. An OPFS signed-evidence journal supplements the short live replay logs; unsupported legacy manifests and attachments exceeding the budgets are reported as omissions.

Checkpoint policy: signed wires in the five existing replay buckets, encrypted structured bodies (256 KiB), thumbnails (1 MiB), and media/files (2 MiB plaintext, plus the cipher envelope) are admitted with a 20 MiB raw-body budget and 30 MiB checkpoint limit. Original storage names and bytes are preserved; legacy structured manifests with unknown names are omitted. Restore validates the entire checkpoint and all signatures before adding blobs, checks every returned CID, and awaits the existing history receivers in timestamp/log order. A CID mismatch is an app-level omission diagnostic, never a rewritten signed CID.

Auto/Custom/Off settings are signed, retained, replayed in misc, and ordered by revision, DID and original wire ID. Custom and Off are carried in invites as bootstrap hints, superseded by verified shared settings. Escrow discovery uses shared extra-room leases on the existing node; exact-room peer handlers isolate provider connections from application greetings and presence.

Each room controller fetches before writing, listens for late providers, debounces for 5 seconds with a 30-second maximum, unions checkpoints on CAS conflicts with at most three PUT attempts, and retries failures with backoff. Watermarks are isolated by effective endpoint and advance only after the portable client's matching ACK. Pagehide and room switches flush best effort. There is no startup gate when no provider exists.

Real-mistl interoperability, daemon restart durability and multi-browser E2E belong to the orchestrator. The journal is seeded only from available verified logs; evidence lost before this upgrade cannot be recreated. Accepted DMs restore through the same awaited background persistence path, with historical badges and notifications suppressed. Attachments omitted by size/budget, unavailable bodies and unknown legacy storage names remain visible in the panel.

Revision-2 retention policy (orchestrator override of the unlimited wire union): the parser and writer share a 20,000-wire limit per bucket. Unions retain the newest wires by timestamp, then ID (full-record canonical order breaks remaining ties), while always pinning the escrow-config winner by (rev, fromId, id). Optional `droppedWires` per-bucket counters persist trimming diagnostics, shown in all panel locales and counted as saved-with-omissions. Merge takes the maximum prior counter per bucket to avoid doubling shared ancestry, then adds records removed from the new union; these count pruning events, not globally distinct lost records. Older checkpoints without this field remain valid and older parsers ignore it. No schema, mistl protocol, or portable-core changes are required.

After wire retention or any blob removal, admitted references are recomputed from remaining bodies, and thumbnails without an admitted parent are omitted. Shared thumbnails survive while any admitted parent remains. Every PUT attempt parses the exact final fitted plaintext with parseCheckpoint; failure leaves the daemon head and ACK watermark untouched, reports the parser reason, and keeps the save dirty for retry.

Revision-3 application fixes: signed reaction toggles converge by (timestamp, id) per (targetId, fromId, emoji). The existing local reaction key reads legacy target-to-reactions indexes and writes a versioned record containing reactions plus compact stamps atomically. Removal stamps survive post trimming; unstamped legacy calls cannot overwrite stamped state. These stamps are application persistence and preserve ordering during replay. Ordinary app joins (active rooms, background DMs, invite sends) retain one page-session lease per room in the same refcount as escrow handles, preserving the existing stay-joined-until-reload policy. Permanent review reproductions are in replayOwnership.test.ts, with ordering and ownership edge cases in reactionOrdering.test.ts and mistTransport.test.ts.

SPEC2 W3: appendWireLog captures every admitted post/reaction/edit/delete/config record before the 600-wire replay window can evict it, including duplicate-ID equivocations (the journal dedupes full canonical signed records). The per-room key is tc-chat:escrow-journal:v1:<roomId>. OPFS mutations are serialized per room, verified records are unioned with persisted evidence, and failed reads never replace the old journal. Failed writes retain the bounded in-memory state for retry. Clean cached journals are limited to eight; records waiting for failed storage remain until a successful write. Checkpoint collection and initial restore union the journal with the live logs and fetched checkpoint. Both journal and checkpoint use the existing newest-20,000-per-bucket policy, including the retained configuration winner and droppedWires counters shown by every existing panel locale.

New post/reaction/edit/delete/config wires and invite DMs sign the transport roomId. Active and background receivers reject a present mismatching roomId before persistence; legacy wires without the field remain accepted. Fixed roomBinding.fixture.ts vectors pass the frozen pre-W3 browser canonicalizer. The Rust proof script extracts the actual mistl chat_relay verify_wire and its wiresign/identity helpers into an isolated harness under ignored node_modules/.tmp, proving the same canonical payloads and signatures without modifying mistl. Its relay intentionally still ignores escrow-config as a wire type; the proof confirms signature compatibility, not new relay configuration replay support.

Legacy random-name body restore remains deferred: mistlib needs a bounded original-manifest/name export or import API to recreate those CIDs. Current encrypted bodies retain their original enc.bin name and CID checks. No cross-repository change is required by W3.

W3 adversarial fixes: every journal read/merge/write runs inside the origin-wide Web Lock named by its room journal key and rereads OPFS before writing. If Web Locks are unavailable, snapshots fail without replacing durable evidence. Full-record deduplication notifies the escrow registry even when the short log suppresses the same wire ID; identical retained retransmissions stay deduplicated. Sessions adopt verified live-log settings before journal I/O and apply accepted settings before attempting config persistence. Persistence errors are logged, retained separately as session.persistenceError, and retried every second (also on redelivery), including while Off; disposal cancels retries. Permanent reproductions are in __regression__, and happy-dom's missing Web Locks API is modeled by a shared exclusive test queue.
